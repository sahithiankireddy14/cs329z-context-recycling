# Measuring repeated retrievals in coding agents

Midpoint prototype: detect repeated file views, searches, and commands in public
SWE-agent trajectories, then compare Jev and Mistral classifications. This repository contains the v4
measurement pipeline and results used in Section 4 and Table 1 of the midterm
report, *What Makes Agents Re-Read What They Already Have? Diagnosing the Causes
of Context Recycling in Coding Agents*. Controlled experiments, recall probes,
and harness interventions remain future work.

## Setup

Run from the repository root with Python 3.11+. The core package has no external
runtime dependencies. Tests require pytest. Full data download needs AWS CLI and
curl; fresh classifications require an OpenRouter API key.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
python -m pytest -q
```

## Reproduce the reported results without API calls

Verify the complete archive and report tables without API calls or data downloads:

```bash
python scripts/verify_results_v4.py
```

This checks all nine SHA-256 checksums, prediction completeness and duplicates,
exactly recomputes model agreement and costs, and verifies consensus membership,
dataset totals, and the 21/77/10/14 groups in report Table 1. It fails with a
nonzero exit status on any mismatch. The same check runs in GitHub Actions.

To also write the recomputed comparison to a local file:

```bash
mkdir -p results
python -m context_recycling.cli compare \
  --left artifacts/v4/sweagent_full_jev_predictions_v4.jsonl \
  --right artifacts/v4/sweagent_full_llm_predictions_v4.jsonl \
  --output results/recomputed_comparison_v4.json
```

The comparison should match the archived statistics exactly. Recorded latency
and cost describe the original calls, not the offline recomputation.

## Rebuild the full dataset and deterministic evidence

Source: the public SWE-bench Verified submission `20240402_sweagent_gpt4`,
generated by SWE-agent with `gpt-4-1106-preview`. The downloader contains the
public S3 and official results URLs. We use all 496 available trajectories;
this is a single older model/harness configuration.

```bash
python -m pip install awscli
bash scripts/download_sweagent_full.sh
python -m context_recycling.cli convert-sweagent \
  --input-dir data/raw/sweagent_gpt4_20240402/trajs \
  --results data/raw/sweagent_gpt4_20240402/results.json \
  --output data/processed/sweagent_gpt4_full_v4.jsonl
python -m context_recycling.cli detect \
  --events data/processed/sweagent_gpt4_full_v4.jsonl \
  --output results/sweagent_full_candidates_v4.jsonl
python scripts/audit_trajectory_evidence.py
```

Expected: **10,330 events and 1,545 candidates**: 585 file views, 98 searches,
and 862 commands. The candidate file is approximately 220 MB. Raw and processed
data are excluded by `.gitignore` and regenerated locally.

Reproduce the consensus dataset and matching-evidence groups using saved labels:

```bash
cp artifacts/v4/sweagent_full_jev_predictions_v4.jsonl results/
cp artifacts/v4/sweagent_full_llm_predictions_v4.jsonl results/
bash scripts/check_saved_v4_results.sh
```

This runs tests, validates full normalized-trajectory coverage for each candidate,
checks prediction completeness and duplicates, verifies the candidate SHA-256
against the original run manifest, and regenerates `results/results_v4.json`
and the evidence groups. It requires the regenerated outputs to equal the archive.
The commands above have been checked locally with Python 3.13.5 and pytest 9.2.0.

For tmux after preparing the data and predictions:

```bash
tmux new-session -d -s v4-repro-check -c "$PWD" \
  'bash scripts/check_saved_v4_results.sh > results/reproduction_check_v4.log 2>&1'
tail -f results/reproduction_check_v4.log
```

`results/reproduction_check_v4.exitcode` contains `0` on success. Finished tmux
sessions may disappear; logs and exit codes remain.

## Run fresh classifications

Create a local `.env` using `.env.example` and set `OPENROUTER_API_KEY`. The key
is excluded by Git. Rebuild the v4 candidate file first, then run in a fresh
results directory to avoid mixing new API calls with archived predictions:

```bash
tmux new-session -d -s reread-v4-fresh -c "$PWD" \
  'RUN_RESULTS_DIR=results/fresh_v4 bash scripts/run_full_classifier_comparison.sh'
tail -f results/fresh_v4/jev_full_run_v4.log
tail -f results/fresh_v4/llm_full_run_v4.log
```

Activate the project Python environment before starting tmux and ensure `python`
in the session resolves to it. The script uses eight workers per classifier,
checkpoints predictions, retries transient errors, and creates
`results/fresh_v4/jev_vs_llm_comparison_v4.json` when both finish. Resume an
interrupted identical experiment using the same directory. Use a new directory
if the dataset, evidence, rubric, or model changes.

Requested models: `typesafe/jev-1.14` and
`mistralai/mistral-small-3.2-24b-instruct`. The original returned Jev model was
`typesafe/jev-1.14-20261014`; returned models are saved per prediction.
Both use the same evidence and rubric; Mistral uses temperature 0. Fresh API
outputs and costs can vary even with identical settings. Archived predictions
provide exact reproduction of the reported numerical results.

## Evidence and interpretation

File candidates match the same file with at least five overlapping lines;
searches match exact queries in compatible scopes; commands match exact text.
Failed reads and advancing consecutive scrolls are excluded. Stuck scrolls are
eligible. Each current retrieval pairs with its nearest earlier match.

Candidates preserve preceding/intervening/following events, raw reasoning, and
pre-action state. `content_unchanged` for file views compares shared numbered
lines only. Inspect `evidence.line_delta` for newly shown and changed lines, and
`history_line_delta` for comparison with earlier observations. Failed edit
previews do not update file history; successful or uncertain edits invalidate
old line coordinates. Shell writes and command dependencies are not fully tracked.

The rubric labels a retrieval legitimate when it supplies useful new/changed
information or serves a supported new purpose; verification when unchanged
information immediately prepares an edit; redundant when already available
information is retrieved without a supported useful purpose. Model requests
include the recorded event sequence with per-observation character limits.
Later actions are retrospective evidence, not information available at the time.
The exact rubric is in `src/context_recycling/classifiers.py` and the archived
run manifest.

Matching thought text is stated reasoning equality, not proof of intent or waste.
Different wording does not establish different goals. The logs do not prove
live-context retention. Agreement is not accuracy, and no causal or intervention
effect is established by this midpoint.

## Files

- `src/context_recycling/`: converter, detector, evidence, classifiers, CLI.
- `tests/`: unit and regression tests.
- `artifacts/v4/`: saved predictions, summaries, evidence audits, manifest,
  and SHA-256 checksums; approximately 2.3 MB.
- `artifacts/v4/consensus_redundant_candidates_v4.jsonl`: all 153 consensus
  candidates. `consensus_file_read_audit_v4.jsonl` contains the 122 file views
  and their evidence groups used as the remaining project's working dataset.
- `scripts/`: data download, experiment, checks, and result generation.

Report-to-artifact mapping:

| Report item | Archived source in `artifacts/v4/` |
|---|---|
| Section 4: events and candidate counts | `sweagent_full_evidence_v4_summary.json` |
| Section 4: classifier labels, agreement, kappa, cost | `jev_vs_llm_comparison_v4.json` |
| Section 4: consensus counts and trajectory coverage | `consensus_file_read_audit_v4_summary.json` |
| Table 1: file-view evidence groups | `consensus_file_read_audit_v4.jsonl` |
| Combined machine-readable results | `results_v4.json` |
| Original candidate hash, rubric, and run completion | `classifier_run_v4_manifest.json` |

To intentionally refresh the committed archive after a validated experiment, run
`bash scripts/package_results_v4.sh`. This overwrites the archive and regenerates
this README; use the read-only verification command for ordinary reproduction.

Working results and raw/processed data remain local. The original manifest
records the candidate hash and rubric; changes to upstream data can change
regenerated evidence. The 122 consensus file
views are the working dataset for the remaining project, with the evidence
groups distinguishing stronger and weaker repetition evidence. Future stages
are controlled context changes, recall probes, and harness interventions.
